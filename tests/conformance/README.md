# cpp11's conformance suite

The measuring instrument for the road to strict ISO/IEC 14882:2011 (Phase 0 of the plan in
`cpp11-1.30-verification.md`, Fable 5.1, 2026-10-28). Every case was judged valid or ill-formed by
clang++ 22.1 `-std=c++11 -pedantic-errors` on cpp11's own headers; every valid case was built and run by cl
14.52 (`/EHsc /O2 /MT /permissive-`), and its output is the expectation.

`cases.tsv` lists every case: `kind` pos or neg; `check` is `output` (the output and exit code must be cl's),
`run` (the exit code only - the output is unspecified, `note` says why) or `own` (cl is the one that is wrong,
`note` says how; cpp11's conforming output is the expectation). A program the oracles found unspecified, or one
whose probe was wrong, is not in the suite at all; neither is an ill-formed program that needs no diagnostic.

`baseline.tsv` is the verdict of every case at `-O0` and `-O2` for the release it was frozen at; it is 1.63's
for the 1,982 cases the suite held then, which 1.64 and 1.65 pass the same, with p167's two frozen at 1.65
(2026-11-11: 1,095 of 1,095 valid programs pass at -O0 and at -O2, 889 of 889 ill-formed ones are refused)
and p168's four at 1.67 (2026-11-13: 1,096 of 1,096 valid programs pass at -O0 and at -O2, 892 of 892
ill-formed ones are refused, none regressed; the library census, which needs Python, was not run)
and p169's three at 1.68 (2026-11-13: 1,099 of 1,099 and 892 of 892, none regressed)
and p170's two at 1.69 (2026-11-18: 1,101 of 1,101 and 892 of 892, none regressed)
and p171's one at 1.71 (2026-11-18, with RTS6x 1.6: it passes at both levels, on Microsoft's CRT and on GRIDE's
runtime; 1,102 valid programs now, the other 1,101 not run again - the compiler is 1.71's). The whole suite at
1.72, which changes the C6000's code alone (2026-11-18): 1,102 of 1,102 and 892 of 892, none regressed.
And p173's one at 1.73, whose change is `<tuple>`'s alone (2026-11-19: a map keyed by a pair, indexed with an
rvalue key, which the cppparse example at cpp's 5f463e2 does and 1.72 refused): 1,103 of 1,103 and 892 of 892,
none regressed.

## Running it

    powershell -File run-conformance.ps1 [-Cpp11 <cpp11.exe>] [-Filter <regex on set/group/case>] [-Levels -O0,-O2] [-Out <dir>]
    python -I library\census.py [--cpp11 <cpp11.exe>] [--out <dir>]

The default compiler is `GRIDEd\x64\Release\cpp11.exe` of this tree; `masm.exe` and `link.exe` are taken from
beside it, and Microsoft's CRT through vswhere (so Visual Studio must be installed to link). cl and clang are not
needed: their verdicts are recorded. Both scripts print what was fixed (gained) and what regressed (lost) against
the baseline, and exit 1 on a regression. A case that times out is run again alone before its verdict
counts: a program that ends by `std::terminate` can stall in Windows Error Reporting on a busy machine.
Once a release's gate is green, `-Freeze` (and `census.py --freeze`) writes its verdicts as the new baseline.
Nothing goes through cmd.exe.

## On the C6747

    powershell -File run-conformance-c6747.ps1 [-Cpp11 <cpp11.exe>] [-Filter <regex>] [-Levels -O0,-O2] [-Out <dir>] [-Freeze]

The same cases with `-arch tms6747`: each valid program is assembled by `asm6x`, linked by `lnk6x` against
`rts6x.lib` with the flat memory map GRIDE's own builds write, and run on `sim6747`; its output is compared with
the recorded one, line ends aside. The verdicts are kept in `baseline-c6747.tsv` and a later run exits 1 when a
case that passed no longer does. **The expected output is Windows'**, so a verdict of `differs` is a difference to
read, not at once a defect.

Measured at cpp11 1.73 with RTS6x 1.6 (2026-11-19), the same at `-O0` and `-O2`: **1,048 of 1,103 valid programs
pass** (1,047 of 1,102 at 1.71 and 1.72; 1,044 of 1,101 with RTS6x 1.5; 1,008 of 1,096 at 1.67, the first whole run; 996 of 1,090 at 1.62) and
891 of 892 ill-formed ones are refused. The 55 that do not pass, and the one accepted:

| | cases | what |
|---|---|---|
| the expectation is Windows' | 41 differ | the size of a pointer, `size_t`, `fpos_t` and the fast integer types, `%p`'s spelling, a hash of a 32-bit `size_t` and the bucket order it gives (29); Microsoft's vtordisp layout; `%a`'s digits; `numeric_limits<int>::traps`; `__STDC_HOSTED__` 0; a stack overflow Windows ends and the C6747's larger stack does not; `terminate`'s exit status; `1 << 62` as a `size_t` (2); `argc`, which is 0 on the simulator (3); `set_terminate`'s first answer, a null pointer for the default handler where Microsoft's runtime answers a function ([get.terminate]'s note allows either) |
| a last digit | 1 differs | `acosh(2.0)` one unit in the last place from Microsoft's (l7a cmath_c99_names) |
| documented in `docs\EXCLUSIONS.md` | 3 differ, 1 accepted | a pointer caught by reference; `bad_typeid` and a null `typeid` (2). Accepted: r1n10, `thread_local`'s address as a template argument |

| tests of Windows itself | 3 do not link | `CreateThread` (w6\tl) |

**What the runs on the C6747 found, and what became of it.** At 1.67, the first whole run: `q - p` of two pointers
not of type `std::ptrdiff_t` (f130 ex24) and the `type_info` of a class named only in an exception specification
not emitted (q200 b33) - mended in cpp11 1.68, set p169. A failed `dynamic_cast<T &>` did not link - RTS6x 1.3 has
`__cxa_bad_cast`. Twenty-three functions of C90's and C99's library were missing behind eighteen programs that did
not link - RTS6x 1.4 has them (IMPLEMENTATION-DEFINED.md names them, and the wide-character library that is
still not there). The locals of a handler an exception leaves stood (w6 eh05, eh09; an exclusion until then) -
mended in cpp11 1.69, set p170, whose first program then showed x86_64-windows leaving a handler's by-value
parameter standing, mended with it. A violated `noexcept` or `throw(T...)` list never reached the program's handlers (w6 nx01, ux01-05, p160 eh02; an exclusion) - cpp11 1.71 calls `std::terminate` where its pad called `abort`, and RTS6x 1.5's unwinder takes a list with types for the barrier it is and enters `__cxa_call_unexpected` from the function's caller. `exception_ptr`, `current_exception` and
`rethrow_exception` did not link (l7a exception_ptr_and_nesting, p155 lt01-03; an exclusion) - RTS6x 1.6 counts
who holds an exception object and has them, set p171; two of the four pass, and the two that start a thread end
where `std::thread`'s constructor throws.

Two cases need minutes on the simulator (r125 op12 at `-O0`, p154 lr02), hence the script's long limits.
